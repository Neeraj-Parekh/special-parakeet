  1003→## The "Agentic" Layer (Day 5 Add-on)
  1004→
  1005→You were right to be scared of unconstrained agents. Here's how you add agentic capability **safely**:
  1006→
  1007→```python
  1008→# src/agents/bounded_agent.py
  1009→from typing import List, Literal
  1010→
  1011→class BoundedAgent:
  1012→    """
  1013→    Agent that can ONLY perform pre-approved actions.
  1014→    No LLM decides money movements. Ever.
  1015→    """
  1016→    
  1017→    ALLOWED_ACTIONS = {
  1018→        "score_order": {"params": ["order_id"], "cost": 0},
  1019→        "request_otp": {"params": ["customer_id"], "cost": 1},
  1020→        "flag_review": {"params": ["order_id", "reason"], "cost": 2},
  1021→        "block_order": {"params": ["order_id", "reason"], "cost": 10, "requires_approval": True}
  1022→    }
  1023→    
  1024→    def __init__(self, risk_api_client, approval_queue):
  1025→        self.client = risk_api_client
  1026→        self.approval = approval_queue
  1027→    
  1028→    def act(self, intent: str, params: dict) -> dict:
  1029→        if intent not in self.ALLOWED_ACTIONS:
  1030→            return {"error": "Action not in allowlist", "blocked": True}
  1031→        
  1032→        action = self.ALLOWED_ACTIONS[intent]
  1033→        
  1034→        # High-cost actions require human approval
  1035→        if action.get("requires_approval"):
  1036→            self.approval.submit(intent, params)
  1037→            return {"status": "pending_approval", "ticket_id": str(uuid4())}
  1038→        
  1039→        # Execute bounded action
  1040→        if intent == "score_order":
  1041→            return self.client.score(params["order_id"])
  1042→        elif intent == "request_otp":
  1043→            return self.client.send_otp(params["customer_id"])
  1044→        
  1045→        return {"error": "Unknown execution path"}
  1046→```

  1228→## 3. Service Breakdown (What Each Agent Builds)
  1229→
  1230→### 3.1 Risk Scorer Service
  1231→**Responsibility:** The core scoring engine. Receives order payload, fetches features, runs model, returns decision.
  1232→
  1233→**API Endpoints:**
  1234→- `POST /v1/risk/score` — synchronous, <100ms p99
  1235→- `GET /v1/risk/health` — deep health check (model loaded, feature store reachable)
  1236→- `GET /v1/risk/metrics` — Prometheus format
  1237→
  1238→**Internal Flow:**
  1239→1. Validate request (Pydantic v2 strict)
  1240→2. Check circuit breaker state
  1241→3. Call Rules Engine (fast path, <5ms)
  1242→4. If rule fires → return immediately with rule trace
  1243→5. If no rule → fetch online features from Feature Store
  1244→6. Run model inference (HistGB, cached model object)
  1245→7. Generate SHAP-like explanation (one-at-a-time perturbation)
  1246→8. Log to Audit Service (async, via message queue)
  1247→9. Return structured response
  1248→
  1249→**Dependencies:** Feature Store, Model Registry, Rules Engine, Audit Service, Message Queue
  1250→
  1251→**Database:** None (stateless, reads model from shared volume/registry)
  1252→

  1287→### 3.3 Feature Store Service
  1288→**Responsibility:** Unified feature serving. Eliminates training-serving skew.
  1289→
  1290→**Architecture Pattern:** Virtual Feature Store (maps logical features to physical storage)
  1291→
  1292→**Components:**
  1293→- **Online Store:** Redis (latest values, <5ms retrieval)
  1294→- **Offline Store:** PostgreSQL + Parquet files (historical, point-in-time correct)
  1295→- **Registry:** PostgreSQL table (feature metadata, lineage, owner)
  1296→
  1297→**Feature Types:**
  1298→| Type | Storage | Latency | Example |
  1299→|---|---|---|---|
  1300→| Static | Online + Offline | <1ms | `is_cod`, `product_category` |
  1301→| On-Demand | Computed at request | <10ms | `address_length`, `hour_of_day` |
  1302→| Streaming | Online (Redis) + Offline (Parquet) | <5ms | `rolling_7d_return_rate` |
  1303→| Batch | Offline only (training) | N/A | `customer_lifetime_value` |
  1304→
  1305→**API Endpoints:**
  1306→- `GET /v1/features/{entity_type}/{entity_id}` — fetch online features

  1310→
  1311→**Critical:** Every feature has `feature_name`, `data_type`, `owner`, `freshness_sla`, `online_store`, `offline_store`, `description`.

  1348→### 3.5 Audit Service
  1349→**Responsibility:** Tamper-evident, append-only audit trail. Court-admissible.
  1350→
  1351→**Data Model:**
  1352→```sql
  1353→audit_records:
  1354→  - prediction_id (PK, UUID v4)
  1355→  - order_id
  1356→  - merchant_id
  1357→  - request_payload (JSONB)
  1358→  - feature_snapshot (JSONB)  # exact features used at inference time
  1359→  - model_version
  1360→  - probability
  1361→  - risk_score
  1362→  - decision
  1363→  - rule_fired (nullable)
  1364→  - explanation (JSONB array of SHAP-like values)
  1365→  - timestamp (UTC, indexed)
  1366→  - previous_hash (SHA-256 of previous record)

  1470→## 4. The Agentic Layer (Phase 2 — Thin Plugin)
  1471→
  1472→**Location:** `Agent Gateway Service` — sits as a consumer of the Risk API, not as a controller.
  1473→
  1474→**Design:** The agent **cannot** call payment APIs, refund APIs, or modify orders. It can only:
  1475→1. `risk.score(order_id)` — get risk score
  1476→2. `risk.explain(prediction_id)` — get explanation
  1477→3. `case.create(order_id, reason)` — create review case
  1478→4. `notify.merchant(merchant_id, message)` — send alert
  1479→5. `rules.suggest(condition, action)` — suggest new rule (pending admin approval)
  1480→
  1481→**Guardrails:**
  1482→- Action allowlist (hardcoded, not LLM-decided)
  1483→- Every agent action is logged via Audit Service with `actor: "agent:{agent_id}"`
  1484→- High-cost actions (block, refund suggestions) require human approval queue
  1485→- Agent has no direct DB access — only API calls
  1486→- Agent prompt is deterministic (no open-ended LLM reasoning on money)
  1487→
  1488→**Why this wins:** Other teams show chatbots that "intelligently" refund orders. You show an agent that **physically cannot** perform unbounded actions, with cryptographic proof in the audit trail.

  1517→## 6. Security Model
  1518→
  1519→### 6.1 Zero Trust Between Services
  1520→- **Gateway → Services:** JWT with short expiry (5 min), signed with RS256
  1521→- **Service → Service:** mTLS (mutual TLS) certificates
  1522→- **Service → DB:** Connection pooling with dedicated DB user per service
  1523→- **Secrets:** HashiCorp Vault or Docker Secrets (for hackathon)
  1524→
  1525→### 6.2 Data Protection
  1526→- **At Rest:** PostgreSQL encrypted (LUKS), Redis encrypted (Redis ACL + TLS)
  1527→- **In Transit:** TLS 1.3 everywhere
  1528→- **PII:** Address fields hashed (SHA-256) in audit logs. Original address only in encrypted DB column.
  1529→- **API Keys:** Hashed with bcrypt, never stored plaintext
  1530→
  1531→### 6.3 Compliance Posture
  1532→- **RBI PA Guidelines:** Data localization (all data stays in India region)
  1533→- **PCI DSS:** Tokenization of sensitive fields, audit trail completeness
  1534→- **GDPR-style:** Right to explanation (every decision has SHAP), right to deletion (soft delete + anonymization)
